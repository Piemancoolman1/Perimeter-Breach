Asset Brief · Perimeter Breach

Playable Character Model

One humanoid character for a browser shooter — rounded, soft, chunky style, not the blocky placeholder look. Everything below is what I need to drop it straight into the game — send it as a single .glb when it's ready.

FIG. 1 — SCALE & POSE REFERENCE UNITS: METERS
01 / STYLE

Rounded & chunky — think PEAK, not a tech demo

New direction, replacing the old blocky look: soft, rounded, toy-like proportions — capsule-ish limbs, a rounded head, smooth curved surfaces instead of flat panels and hard corners. PEAK is the closest touchstone — stylized and a little cute, not realistic.

Smooth-shade the curved surfaces (soft normals, not faceted) — that's what actually reads as "rounded" rather than just a low-poly ball. Curves need more geometry than flat boxes did to look clean; roughly 4,000–8,000 triangles for the whole character is a reasonable target. Materials stay simple either way — flat base color plus roughness/metalness, no hand-painted texture work needed.

02 / SCALE

~1.75m tall, standing, feet at the origin

Model at real-world scale (1 unit = 1 meter), Y-up, standing in a neutral A-pose or T-pose with feet resting on y = 0. Face a single consistent direction — it doesn't matter which way, just be consistent so I can line it up on import.

03 / PIECES

Keep head, torso, arms & legs as separate objects

Don't weld the body into one continuous mesh. When a character dies in the game it breaks apart into its individual limbs, each one flying off on its own — that only works if the file actually contains six separate objects (head, torso, armL, armR, legL, legR), touching at the joints but not merged/boolean'd into a single piece.

With rounded parts specifically, let each piece overlap slightly into its neighbor at the joint (a flush butt-join that worked fine for flat boxes will show a visible seam/gap on a curved surface).

This is the one easy-to-miss step — it's a normal thing to clean up during modeling, so flag it for whoever does the final export pass too.

One more thing on armR: don't model a weapon into its hand. The gun is a separate piece the game attaches in code, so every class can hold a different one. Just pose/shape the hand as if it's gripping something roughly pistol-sized — a loose fist with the index finger forward is plenty.

04 / RIG

Pick one — static is the easier start

Static meshRECOMMENDED FIRST PASS

No skeleton — just the six separate, posed pieces from above. I can still make it walk, turn, aim, and break apart on death in code. Smallest scope, and it's what supports the death effect directly.

Rigged & skinnedLATER, IF WE WANT ANIMATION

Standard bipedal skeleton, one continuous mesh weight-painted to it. Buys a real animated walk cycle, but a single skinned mesh can't break apart the same way — we'd need a separate solution for the death effect if we go this route. Worth doing once the static version is proven out.

05 / EXPORT

glTF 2.0, as a single .glb

Cinema 4D exports this natively. One file, textures embedded — no loose image files to keep track of. That's the format the game's engine (three.js) reads directly.

Questions on any of this — just ask. Happier to clarify up front than redo the model after.
